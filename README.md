물리 기반 주행 · 교통 혼잡 · 큐잉 이론 · 몬테카를로 통계 검증을 통합한
**스마트물류 AGV/AMR 디지털 트윈 설계·검증 플랫폼**.

모델 정밀도 · 분석 깊이 · 코드 구조 · UX 전 영역을 비쥬얼스튜디오로 재설계한 버전입니다.

## 2. 원본 대비 개선 사항

### 2.1 시뮬레이션 모델 정밀도

| 영역 | 원본 | PRO |
|---|---|---|
| **주행** | 등속 직선 (`속도 × dt`) | **사다리꼴 속도 프로파일** (가속→정속→감속), 짧은 구간은 삼각 프로파일 자동 전환 |
| **선회** | 없음 | 방향 전환각에 따른 **선회 감속** + 각속도 제한 |
| **차량 간섭** | 없음 (서로 통과) | **차간 안전거리 추종 감속**(IDM 간이형) + 공간 해시 근접 탐색 |
| **통로 혼잡** | 고정 "교통 마진 %" 슬라이더 | **간선 용량·차간거리·이상화** 3종 선택, 교착 방지/처리량 우선 포트 배차 정책 및 막힌 간선을 제외한 우회 경로 재탐색 |
| **배터리** | "분당 N% 소모" 임의값 | **에너지 수지**: 소비전력(W) × 시간 ÷ 용량(kWh), 적재 시 추가 전력 분리 |
| **하역 시간** | 고정 상수 | **로그정규 분포**(변동계수 CV 설정 가능) |
| **수요 도착** | 고정 주기 | 공통 주기 또는 **픽업대별 독립 배출 주기** + CV 기반 불규칙 도착 + 피크 시간 배율(사인파) |
| **픽업→드롭 흐름** | 드롭대 랜덤 선택 | 전체 랜덤 배정 또는 **픽업대별 허용 드롭대 1~2곳 지정** |
| **포트** | 1대만 점유 가능 (하드코딩) | **포트당 동시 수용 대수(c) 설정** + 대기행렬 추적 |
| **고장** | 없음 | **MTBF/MTTR 고장·복구 모델** (지수분포) |
| **재현성** | `Math.random()` — 재현 불가 | **시드 기반 결정론적 PRNG** (mulberry32) — 동일 시드 = 동일 결과 |

### 2.2 Capa 산정 방법론

| 영역 | 원본 | PRO |
|---|---|---|
| 소요 대수 | `실측×0.7 + 이론×0.3` 휴리스틱 | **혼잡·큐잉 반영 처리량 곡선 기반 역산** |
| 감도 곡선 | `n × 단대capa` **선형 외삽** | **비선형**: Greenshields 밀도-속도 혼잡 + Erlang-C 포트 대기 **반복 수렴** |
| 포트 대기 | 단순 카운트 | **M/M/c 대기행렬 해석 모델** |
| 병목 진단 | 3분기 if-else 텍스트 | **10종 자동 진단 엔진** (고립 노드, 경로 단절, 포트 포화, 혼잡, 충전 인프라, 부하 불균형 등) |
| 경로 탐색 | O(V²) Dijkstra, 캐시 없음 | **이진 힙 O(E log V)** + 경로 캐시 + 방향성(일방통행) 간선 + 교착 간선 제외 재탐색 |

### 2.3 신규 기능 (원본에 없음)

- **🧪 실험실**
  - **파라미터 스윕** — 임의 변수 범위를 분할해 민감도·**탄력도** 자동 계산
  - **몬테카를로** — 시드를 바꿔 N회 반복, **95% 신뢰구간**과 변동계수 산출 (워밍업 구간 자동 제외)
  - **시나리오 A/B/C 비교** — 설계 대안 나란히 평가, 최적안 자동 하이라이트
- **💰 경제성 분석** — CAPEX/OPEX, 인력 대체 환산, **투자 회수기간**, 5년 ROI, 건당 처리원가, 최소 원가 구성 추천
- **전역 최적 배차** — **헝가리안 알고리즘 O(n³)** 으로 차량×작업 총 비용 최소화 (기아 방지 aging 포함)
- **📑 종합 리포트** — 10개 섹션 텍스트 리포트 내보내기
- **🎥 결과 영상 내보내기** — 시뮬레이션 맵과 주요 KPI를 16:9 화면으로 합성해 브라우저에서 WebM 영상으로 녹화. 긴 녹화는 브라우저 메모리 사용량이 증가할 수 있습니다.
- **혼잡 히트맵** — 간선별 실시간 혼잡도 색상 시각화
- **노드 인스펙터** — 클릭 시 상태 확인 + 이름/수요 가중치 편집 및 대기존 점유 확인
- **자동 연결(🪄)** — 근접 노드 자동 통로 생성 + 고립 노드 강제 연결
- **레이아웃 프리셋 5종** — 표준 스마트공장 그리드(표준·좁음) / 단방향 루프 / 크로스도크 / 피쉬본. 모든 픽업대·드롭대·대기존에 두 개의 접근 링크를 둡니다. 간선 예약 교통은 좁음 그리드에서 시험하는 것을 권장하며, 기본 통행 모델은 이상화입니다.
- **픽업대별 도착 드롭 설정** — 맵에서 픽업대별 허용 드롭대 1~2곳 지정, 자동 배출·랜덤 작업 생성에 적용, 개별 등록·CSV는 입력 목적지 유지
- **픽업대별 화물 배출 주기** — 좌측의 동일 적용 체크를 끄고 맵에서 픽업대를 선택해 인스펙터에서 주기를 지정. 비워두면 공통 주기를 사용
- **포트 배차 정책** — 진행 중인 운행이 포트를 예약하는 교착 방지 우선 방식 또는 픽업 완료 후 다음 작업을 바로 배차하는 처리량 우선 방식 선택
- **localStorage 자동 저장** — 12초 주기 + 종료 시 저장, 재방문 시 복원
- **단축키 · 터치 제스처(핀치 줌/팬) · 모바일 반응형**

### 2.4 코드 구조

원본은 단일 HTML 4,027줄에 CSS·HTML·엔진·UI가 모두 혼재했습니다.
PRO는 **책임 분리된 8개 모듈**로 재구성했습니다.

```
index.html          UI 마크업 (파라미터 입력은 스펙에서 자동 생성)
css/style.css       4개 테마 토큰 + 반응형
js/util.js          시드 PRNG, 최소 힙, 통계(Erlang-C 포함), 포맷터
js/model.js         파라미터 스펙(33종), 레이아웃 그래프, 프리셋
js/graph.js         힙 Dijkstra, 경로 캐시, 혼잡 가중, 속도 프로파일
js/engine.js        로봇 상태머신(13상태), 공간 해시, 시뮬레이션 루프
js/dispatch.js      배차 6종 + 헝가리안 할당
js/renderer.js      Canvas 렌더링 (줌/팬/히트맵/DPR 대응)
js/analytics.js     사이클 모델, 혼잡·큐잉, 진단, 스윕, 몬테카를로, ROI
js/charts.js        Chart.js 래퍼 7종 + 테마 동기화
js/app.js           컨트롤러 (이벤트, 테이블, 내보내기, 상태 저장)
```

## 5. 계산 모델 근거

| 모델 | 적용 이론 |
|---|---|
| 주행 시간 | 사다리꼴 속도 프로파일 — `d ≥ d_acc+d_dec` 이면 정속 구간 포함, 아니면 삼각 프로파일 `v_peak = √(2·d·a·b/(a+b))` |
| 통로 혼잡 | Greenshields 밀도-속도 관계 `v_eff = v·(1−(k/k_jam)^1.35)` + 교차점 간섭 보정 |
| 포트 대기 | Erlang-C (M/M/c) — `Wq = C(c,a) / (c·μ − λ)`, 도착률↔대기시간 반복 수렴 |
| 배터리 | 에너지 수지 — `ΔSoC = (P·t/3600) / (kWh·1000) × 100` |
| 배차 | 헝가리안 알고리즘 (Jonker-Volgenant 스타일) O(n³) |
| 소요 대수 | 처리량 곡선 위 목표 UPH 최초 충족점 탐색 |

> ⚠️ 모든 수치는 **모델 기반 추정치**입니다. 실제 도입 시 현장 실측 검증을 병행하십시오.

## 8. 향후 개선 여지

- **CAD 도입** — 현재 DXF/이미지 업로드 버튼은 UI 상 자리만 확보된 상태입니다. DXF `LINE`/`LWPOLYLINE` 파서와 배경 레이어 정합(스케일 캘리브레이션 UI)이 미구현입니다.
- **Web Worker 병렬화** — 몬테카를로가 메인 스레드에서 실행되어 반복 횟수가 많으면 UI가 잠시 멈춥니다.
- **교통 교착 대응** — 간선 용량 준수, 동일 간선 차간거리 제어, 막힌 간선을 제외한 우회 탐색 및 포트 배차 정책을 적용했습니다. 포트 동시 수용 대수는 실제 점유 차량 수의 상한이며, 만석일 때 후속 AMR은 진입 통로에서 줄을 섭니다. 작업 차량은 포트 영역을 벗어난 뒤 점유를 해제하고, 대기열은 선입 차량부터 진입합니다. 대기존은 점유 차량과 이동 중인 진입 예약 차량을 합쳐 구역당 1대만 허용하며, 만석이면 작업 차량은 포트를 비운 가까운 경유 노드에서 기다립니다. 모든 프리셋의 대기존은 두 개의 접근 링크로 연결됩니다. 간선 예약은 주행 중인 단일 간선만 잠그고 노드에 도착하면 해제합니다. 픽업대별 배차 예약 한도는 별도로 설정하며, 실제 포트 점유 상한과 구분됩니다. 처리량 우선은 픽업 완료 후 픽업 슬롯을 즉시 해제하고, 간선 예약 교통의 목적지별 진행 작업은 최대 2건까지 허용합니다. 단일 경로 자체가 차단되거나 연결이 끊긴 레이아웃은 통로 추가·방향 수정이 필요합니다.
- **다층(멀티플로어) / 엘리베이터 모델** 미지원
- **실측 로그 임포트** — 현장 WMS/WCS 로그를 불러와 모델을 보정하는 기능 미구현
